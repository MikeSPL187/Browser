# Функции Vola против топовых браузеров (2026-09-29)

Сравнение с Chrome, Firefox, Safari, Samsung Internet, Vivaldi, Brave, Opera, Arc Search и идеями
Zen Browser. Статус Vola — по коду `main` после слияния PR #1–#17. Приоритеты учитывают правила
проекта: без телеметрии, без сторонних SDK, приватные вкладки ничего не пишут на диск.

**P0** — нужно раньше всего; **P1** — следующий квартал; **P2** — позже; **—** — не делаем.

## Менеджер паролей: почему выбирают лидеров и что берём

| Менеджер | Почему выбирают | Что переносим в Vola |
| --- | --- | --- |
| **Bitwarden** | Открытый код, регулярные аудиты (Cure53), бесплатно без лимита устройств, можно свой сервер | Код открыт (MPL-2.0), бесплатно, без аккаунта; синхронизация без сервера |
| **1Password** | Лучший интерфейс, Watchtower (утечки, повторы, слабые), Secret Key на устройстве, Travel Mode | «Проверка паролей»; ключ живёт только на ваших устройствах, фраза восстановления; скрытие защищённого пространства целиком |
| **Proton Pass** | Приватность, ключи доступа и 2FA-коды даже бесплатно, псевдонимы почты (SimpleLogin) | Ключи доступа и коды 2FA без ограничений. Псевдонимы — позже, только со своим аккаунтом SimpleLogin/addy.io и по явному включению |
| **KeePassXC / KeePassDX** | Никакого облака: файл хранилища ваш, синхронизация через Syncthing | Хранилище работает офлайн, импорт/экспорт `.kdbx`, синхронизация через вашу папку |
| **Google / Apple** | Ничего настраивать не нужно: предложение сохранить и заполнить прямо в браузере | То же удобство: сохранить при входе, заполнить по биометрии, сгенерировать при регистрации |

### Устройство

- **Порт** `CredentialVault` в `shared/commonMain` (без типов GeckoView). Реализация хранилища —
  на Android; адаптер Gecko реализует `Autocomplete.StorageDelegate`
  (`onLoginFetch`/`onLoginSave`/`onLoginUsed`, карты, адреса). В WebView-сборке своего
  автозаполнения нет: там раздел паролей работает как хранилище с копированием, а заполнение —
  через системное автозаполнение. Это явно показано в интерфейсе (правило 1 `CLAUDE.md`).
- **Шифрование:** случайный 256-битный ключ хранилища шифрует записи (AES-256-GCM, аппаратно на
  Android). Ключ обёрнут ключом Android Keystore (StrongBox, если есть) с подтверждением биометрией
  и таймаутом, а также ключом из фразы восстановления из 12 слов.
- **Файл:** одно зашифрованное хранилище, атомарная запись (как `AtomicTabFiles`), исключено из
  облачной копии (как в PR #14). Приватные вкладки ничего не сохраняют.
- **Против фишинга:** заполнение только для точного источника (субдомены — по подтверждению),
  никогда в чужих iframe, только по действию пользователя. Такие же умолчания у Bitwarden.
- **Коды 2FA:** RFC 6238, импорт `otpauth://` из QR.
- **Проверка утечек:** по желанию, выключена по умолчанию. Pwned Passwords с k-анонимностью: на
  сервер уходят первые 5 символов SHA-1 и заголовок с паддингом.
- **«Сменить пароль»:** открывает `/.well-known/change-password` сайта (стандарт W3C).
- **Генератор:** системный CSPRNG; пароли и фразы из словаря EFF.
- **Импорт:** CSV Chrome/Firefox/Proton Pass, JSON/CSV Bitwarden, CSV 1Password, KDBX 4.
  Для KDBX нужен Argon2. **Решение владельца (2026-09-30):** сторонняя открытая библиотека для
  KDBX допустима (не SDK, без сети). Кандидат — kotpass (MIT); перед подключением проверить
  лицензию, активность проекта и отсутствие сетевого кода.

## Синхронизация без своего сервера

1. **Связка устройств.** Первое устройство создаёт случайный ключ группы. Второе сканирует QR
   (одноразовый секрет и публичный ключ X25519), ключ группы передаётся зашифрованным. Запасной
   путь — фраза из 12 слов, как в цепочке синхронизации Brave.
2. **Данные.** Каждая запись (вкладка, пространство, закладка, запись хранилища) шифруется ключом
   группы, идентификаторы записей — через HMAC. Конфликты решаются по полям: последняя запись
   побеждает, часы Лэмпорта, удаления — через tombstone.
3. **Каналы, все необязательны:**
   - **Напрямую по Wi-Fi:** поиск через `NsdManager`, зашифрованный канал на ключе группы.
     Интернет не нужен.
   - **Через вашу папку:** папка выбирается через Storage Access Framework (Syncthing, Nextcloud,
     Диск — любое приложение-провайдер). Каждое устройство пишет только свои зашифрованные файлы,
     поэтому конфликтов на уровне файлов нет.
   - **Сервер Candy Sync** — как сейчас, для тех, у кого он есть.
4. Никаких серверов Vola нет и не будет: владельцу проекта нечего хранить и нечего отдавать.
