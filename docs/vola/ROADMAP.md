## 2. Очередь PR

### 2.1 Как выбран порядок

1. **Фаза A — фундамент.** Зелёный CI, свежий движок, автоматические проверки качества. Без них
   каждый следующий PR проверяется «на глаз», а после обновления Compose его пришлось бы
   перепроверять.
2. **Фаза B — ежедневный путь**, по частоте: ввод адреса (каждый переход) → новая вкладка →
   обзор вкладок → пространства → меню → сведения о сайте. После фазы B каждый экран, который
   человек видит каждый день, сделан по v4. **Веха: первый подписанный релиз.**
3. **Фаза C — фичи Zen и чтение.** Это то, что отличает Vola от Chrome и Firefox.
4. **Фаза D — система:** состояния, настройки, темы, библиотека.
5. **Фаза E — пароли и перенос.** По `features-roadmap.md` это P0, но работа тяжёлая и требует
   аудита, поэтому идёт после того, как оболочка устоялась.
6. **Фазы F и G** — инструменты, первый запуск, планшет, синхронизация.

**Что что разблокирует:**
- Q1 (новый Material 3) → группы кнопок M3 Expressive в Q9, Q16, Q17.
- Q3 (проверки) → автоматическая приёмка всех следующих PR.
- Q5 (Essentials) → ряд Essentials в Q7.
- Q7 (`TabsController`) → Q8, Q14, Q26.
- Q9 (меню) → точки входа для Q11–Q14, Q24, Q28.
- Q15 (компонент состояний) → Q18, Q20.
- Q16 (реестр настроек) → Q17 и настройки каждой следующей фичи.
- Q19 (хранилище) → Q20–Q22.

### 2.3 Карточки PR

#### Фаза A. Фундамент

**Q1. Обновление зависимостей вместо Dependabot #21 и #22** · High · 1 сессия
- **Цель.** Compose BOM 2026.09 и Material 3 1.5 (компоненты M3 Expressive для досок: группы
  кнопок, плавающие панели, индикатор загрузки), AndroidX, Kotlin 2.4.20, Compose Multiplatform
  1.12, kotlinx-serialization 1.11. Затем `currentResources()` → `LocalResources.current`, хелпер
  удаляется. kotlinx-datetime не нужен: единственный `Instant.parse` переходит на `kotlin.time`.
- **Как.** Своя ветка от `main` с версиями из обоих PR: команда `@dependabot rebase` не сработала,
  ветки Dependabot не трогаем. После слияния Dependabot сам закроет #21 и #22.
- **Файлы.** `gradle/libs.versions.toml`, `ui/ComposeResources.kt` и одно место вызова, один файл с
  `kotlinx.datetime.Instant`, исправления новых предупреждений и lint.
- **Порты.** Нет.
- **Риски.** Новые проверки lint. Поведение Compose (отступы, ripple, текст, фокус) ловим полным
  туром снимков. Совместимость Kotlin 2.4.20 и CMP 1.12. Без SDK проверить нельзя: только CI.

**Q2. GeckoView: последняя стабильная версия и ежедневная проверка обновлений** · High · 1 сессия
- **Цель.** Правило 6. В `main` — GeckoView 156 (сборка от 21.09), а Firefox 157 вышел 29.09.
  Скорее всего, вышел и GeckoView 157; maven.mozilla.org из среды закрыт, поэтому версию узнаём
  шагом CI. Воркфлоу `geckoview-update.yml` по `tech-plan.md`, раздел 3: каждый день проверяет
  `maven-metadata.xml` и открывает PR со ссылками на выпуск, API и бюллетени MFSA.
- **Итог (#32).** Холостой прогон в PR нашёл `157.0.20260924084938`, версия поднята. Dependabot
  GeckoView больше не трогает: раз в неделю — слишком редко для точечных выпусков.
- **Файлы.** `gradle/libs.versions.toml`, `.github/workflows/geckoview-update.yml`,
  `scripts/ci/geckoview_latest.py` с тестом, адаптер `browser/gecko/*`, если поменялся API.
- **Порты.** Только адаптер Gecko.
- **Риски.**
  - Удалённые устаревшие API.
  - На динамической панели и safe-area держатся «Остров» и «Рама»: проверяем снимками прокрутки.
  - PR, созданный через `GITHUB_TOKEN`, сам не запускает CI. Воркфлоу запускает *Build* и
    *Screenshots* через `workflow_dispatch`: этот путь `GITHUB_TOKEN` разрешён.
  - Новый воркфлоу нельзя запустить вручную до слияния в `main`. До этого проверяем его
    триггером `pull_request` на изменение самого файла.

**Q3. Проверки качества в CI** · High · 2 PR: **Q3a** — пункты 1–4 (`scripts/ci/quality_gates.py`,
шаг *Quality gates* в *Build*), **Q3b** — пункты 5–7.
- **Цель.** Всё, что можно проверить машиной, проверяется в каждом PR:
  1. **Храповик размера** `quality_gates.py size` + `scripts/ci/size-baseline.json`:
     `BrowserController.kt` (16 093 строки), `MainActivity.kt`, `ui/BrowserScreen.kt`,
     `ui/TabOverview.kt` не растут; уменьшение нужно закрепить (`size --update`).
  2. **Токены** `quality_gates.py tokens`. В добавленных строках вне `ui/theme` запрещены
     `Color(0x…)`, числовые `.dp`/`.sp` (кроме `0.dp`) и `tween`/`spring` с числами. Исключение —
     комментарий `// token-exempt: причина`. Около 1 070 литералов `dp` из кода Candy уходят
     по мере переноса экранов.
  3. **Граница движков** `quality_gates.py engine`: `org.mozilla.geckoview.*` и `android.webkit.*`
     — только в `browser/gecko`, `browser/systemwebview` и `browser/userscript`. Единственное
     нарушение (`AppDataTransferActivity`: версия GeckoView) перенесено в адаптер в Q3a.
  4. **Бренд** `quality_gates.py brand`: слово «Candy» в тексте `values*/strings.xml` — ошибка.
  5. **Доступность в туре снимков.** По дампу uiautomator на каждом шаге: кликабельные
     элементы ≥ 48 dp; у кликабельного без текста есть `content-desc`. Новые нарушения — ошибка.
  6. **Тур снимков.** Новые экраны снимаются со шрифтом 200 % и с выключенными анимациями.
     Холодный старт (`am start -W`, среднее из 5) попадает в сводку. Это ориентир без порога:
     на эмуляторе время шумит.
  7. **Превью.** Аннотация `@VolaPreviews`: светлая, тёмная, шрифт 200 %, узкий и широкий экран.
     Одна аннотация на каждый новый UI.
- **Риски.** Ложные срабатывания проверки токенов: нужен короткий список исключений с причинами.
  Тур станет дольше: проход 200 % и без анимаций — только для шагов, отмеченных как новые.

## 3. Как делается один PR

0. **До кода.** Рекомендую Effort (правило 10). Если задача неясна — план из 3–7 шагов и вопрос
   владельцу. Ветка `claude/<тема>` от свежего `main`, один PR за раз.
1. **Доска.** Рендер доски в Chromium (STATUS → «Заметки о среде»). Выписать элементы и состояния:
   пусто, загрузка, ошибка, тёмная тема, шрифт 200 %, планшет. Сравнить с 2–3 лидерами. Если
   доска слабее — предложение владельцу до кода. Нет доски — нарисовать в языке v4, положить в
   `design/canvas/`, показать, ждать одобрения.
2. **Порт.** Сначала интерфейс, без типов движка, с KDoc «зачем».
3. **Движки.** Реализация в Gecko и WebView. Если в WebView невозможно — флаг `supports*` в
   порте, и UI скрывает фичу.
4. **Логика.** Чистые `*Rules` и контроллер фичи, не в Compose. Новое не добавляется в
   `BrowserController`; трогаемая область выносится из него (правило бойскаута).
5. **UI на токенах.** `VolaColors`, `VolaType`, `VolaShapes`, `VolaSpacing`, `VolaElevation`,
   `VolaMotion`. Состояния читаются в фазе отрисовки. Повторяющееся — в общий компонент.
6. **Строки** сразу в `values/` и `values-ru/`, формы множественного числа;
   `python3 scripts/test_translations.py`.
7. **Превью** `@VolaPreviews`: светлая, тёмная, 200 %, узкий и широкий экран.
8. **Тесты** на каждое правило, включая крайние случаи.
9. **Шаг в туре** `scripts/ci/capture_screenshots.py` для нового экрана или состояния.
10. **Локально:** скрипты `python3 scripts/test_*.py`, сборка чистых частей на JVM без SDK,
    повторное чтение диффа глазами ревьюера.
11. **CI:** *Build* и *Screenshots* (метка `screenshots`). Снимки сравнить с доской;
    расхождения исправить в этом же PR. Падения из `crash-log.txt` — блокер. Красный CI —
    разобрать по логу, не перезапускать «на удачу».
12. **PR** на русском: что и зачем, как устроено, таблица «Vola vs лидер», ссылка на снимки в
    ветке `screenshots`, чек-лист проверки на телефоне, известные ограничения. Подписка на события,
    CI и ревью — до зелёного.
13. **Конец сессии:** обновить `STATUS.md`, этот файл и `NEXT_SESSION.md`. PR не сливаю и
    следующий не начинаю без слова владельца.

Экономия лимита: одно отложенное ожидание CI на все проверки, метка `screenshots` — только при
изменении UI, без повторных запусков.

### 4.1 Как проверяется каждый PR

| Критерий | Как проверяю |
| --- | --- |
| **Красиво** | |
| Только токены, без чисел и цветов | `check_tokens.py` (Q3), ревью диффа |
| Строго по доске | Снимки эмулятора рядом с рендером доски, лист сравнения в описании PR |

| Пустые, загрузочные и ошибочные состояния | Компонент по доске States, шаг тура на каждое состояние |
| **Удобно** | |

| Отмена разрушительных действий | Снэкбар «Отменить» в чек-листе |

### 4.3 Предложения к доскам v4 (нужно ваше решение до кода)

Там, где доска слабее лидера или чего-то не показывает:

- **П1 (Q4).** «Перейти на вкладку» в подсказках, если адрес уже открыт в любом пространстве.
  Строка с самоцветом и названием пространства. У Chrome и Firefox это есть, но без пространств.
- **П2 (Q7).** Морф «вкладка ↔ обзор»: карточка «Рамы» сжимается в свою миниатюру, как в
  Safari. Доска статична, а в Candy уже есть hero-переходы — опираемся на них.
- **П3 (Q7).** Автоархив неактивных вкладок, как у Arc, Chrome и Firefox. Выключен по умолчанию,
  настройка у пространства (через сутки, неделю, месяц). Вкладки уходят в «Отложенные», не
  удаляются.
- **П4 (Q13).** Объединить LinkPeek и Glance в одно действие. Долгое нажатие открывает карточку
  Glance; действия LinkPeek — рядом под ней; «Открыть во вкладке» — потянуть карточку вверх.
  Сейчас это две доски на один жест; правило «одно действие — одно место».
- **П5 (Q11).** В Compact полоска стоит выше системной зоны жестов. Свайп по ней влево и вправо
  листает вкладки, вверх — открывает обзор. Для TalkBack — действие «Показать панель».
- **П6 (Q9).** Набор и порядок плиток меню настраиваются, как у Samsung Internet и Vivaldi.
  Редактор действий в Candy уже есть.
- **П7 (Q5).** Карточка защиты по касанию открывает недельный отчёт, как Privacy Report в Safari:
  по сайтам, только данные устройства. Карточку можно скрыть.
- **П8 (Q8).** Раскладка жестов. Свайп по нижней панели оставить для вкладок: это самый частый
  жест (Arc, Safari), он уже работает. Пространства — свайпом в обзоре вкладок и касанием по
  самоцвету. В `CLAUDE.md` написано «переключение свайпом по нижней панели»: прошу подтвердить
  изменение.
