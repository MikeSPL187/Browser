## 3. Новые находки

Уровни: **Высокий** — потеря данных или нарушение защиты в обычной работе; **Средний** — заметный дефект
или системный риск; **Низкий** — гигиена.

### N-01 · Низкий (мёртвый код) · Немецкая страница синхронизации в `shared` — удалена
`shared/…/shared/ui/settings/SyncSettingsPage.kt` (513 строк, 43 немецких литерала: «Synchronisierung», «Server-Adresse»,
«Verbinden»…) была заготовкой для iOS-приложения (`iosApp/` в репозитории уже нет) и **нигде не использовалась**.
**Поправка к первой версии отчёта:** я утверждал, что страница видна пользователям планшета через
`ui/SettingsScreen.kt:502`. Это было **неверно**: тот вызов ведёт на `app/.../ui/SyncSettingsPage.kt` (тот же пакет,
42 `stringResource`, локализована), а на немецкую страницу не импортировал никто — я принял одно имя за один файл и не
проверил импорты. Пользовательского дефекта не было; был мёртвый код с литералами, которые гейт `literals` и нашёл.
**Сделано (по слову владельца «удаляй»):** удалены файл и его тест `SyncSettingsFormRulesTest` (проверял только правила
этой страницы), правка `docs/sync/app-integration.md`. Дерево теперь без единого литерала: тест
`test_repository_has_no_findings` в `LiteralsTest` держит это для всех будущих правок.

### N-02 · Средний (продукт) · История ограничена 250 записями
`data/BrowsingLibrary.kt:54`: `MAX_HISTORY_ENTRIES = 250`, обрезка в `addHistory` (`:67`). Ни `decisions.md`, ни план
v5 такого лимита не обосновывают — это наследство Candy. Цель «Safari» (поиск по истории, «вернуться к странице
месяц назад») с 250 записями недостижима. Лимит не поднять без переезда: история лежит одной JSON-строкой в
`SharedPreferences` и переписывается целиком синхронным `commit()` на каждый переход (это и есть V-07).
**Исправление:** перенести историю в уже существующий SQLite-слой (`RecallRepository`), индексировать по времени и
профилю, убрать лимит (или поставить 100 тыс.), писать вне главного потока. Закрывает V-07 и N-02 одним шагом.

### N-03 · Средний · Семейство V-02: чтение «всё или ничего» (кроме вкладок)
Один битый элемент превращает весь список в пустой, а следующее сохранение перезаписывает хранилище пустым:
- `BrowserSessionStore.kt:1356–1364` `loadArray` — исключения сайтов и их приватные настройки (`:533`), разрешённые
  всплывающие окна (`:645`), журнал вычёркивания следов (`:294`): один `getJSONObject` бросает → `emptyList()`;
- `BrowserSessionStore.kt:166–191` `loadTabStacks` — группы вкладок: любая запись или `check(array.length() <= MAX)`;
- `data/HistoryJsonCodec.kt:14` — при ошибке разбора всего массива история пуста, следующий `record()` её затирает
  (построчный пропуск, описанный в комментарии, работает только внутри валидного массива);
- `data/SnoozedTabStore.kt:29` — отложенные вкладки: то же, а на них стоят будильники.
Профили сделаны правильно (`WorkspaceProfilesCodec` сохраняет нечитаемые записи) — **это образец для остальных**.
Вероятность низкая (данные пишет само приложение, XML атомарный), цена высокая. **Исправление:** общий
построчный декодер по образцу профилей и тест «одна битая запись, остальные живы» для каждого хранилища.

## 4. Что проверено и сделано хорошо

- **Криптография**: AES-256-GCM, случайный 96-бит nonce, AAD привязывает блок к месту (`VaultCrypto.kt`); ключ в Keystore
  со StrongBox и привязкой к экрану блокировки, 30-секундное окно (`AndroidCredentialVault.kt`); фраза — PBKDF2 600 тыс.
  итераций с границами при чтении («поддельный файл не подвесит приложение»); `fill(0)` после использования.
- **Входящие ссылки**: `BrowserUriPolicy` — запрет управляющих символов, userinfo, схем `javascript/file/content/data/blob`;
  `intent:` разбирается и фильтруется; лимиты 32 КБ; выдача разрешений на внешние приложения привязана к жесту и цепочке
  редиректов с временем жизни 15 с.
- **Обновления**: проверяются хост, путь, MIME, единственность файла, канал сборки; редиректы выключены; ответ ограничен.
- **WebDAV (V27)**: HTTPS-only, системные сертификаты, без редиректов и cookie, ограничение тела, ETag-конкурентность.
- **Пользовательские скрипты**: нет `GM_xmlhttpRequest`; привилегированные права отклоняются; зависимости с SHA-256;
  каталог проверяется хэшем и метаданными.
- **Сервер синхронизации (Go)**: ключ ограничителя — последний элемент `X-Forwarded-For` (тот, что добавил доверенный
  прокси), сравнение в постоянном времени, таймауты чтения/записи, `MaxBytesReader`, контейнер `read_only`, `cap_drop: ALL`.
- **CI**: все действия закреплены по SHA, минимальные права по умолчанию, release-секреты только в job релиза.
- **Локализация**: 2 205 строк en = ru, 63 plurals с формами one/few/many/other, 0 сирот, 0 расхождений плейсхолдеров.
- **v5**: ни одного литерала `dp/sp/Color` вне токенов; зоны касания через `V5Sizes.touchTarget`; единая тактильная
  отдача (`V5Haptics.kt`); `V5Sheet` — образцовый компонент (предиктивный «назад», режим без анимаций, `paneTitle`,
  обработка IME, `testTag` до `clearAndSetSemantics`, как требует `ui/CLAUDE.md`).
- **Ключи списков**: во всех проверенных `LazyColumn/LazyGrid` заданы стабильные `key`.
