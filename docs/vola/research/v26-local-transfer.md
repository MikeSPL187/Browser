# V26: перенос вкладок и закладок по QR (локально)

Шаг 2 плана H (#80, комментарий 6230454687): порт и протокол в `shared`, без Android.
Код — `shared/src/commonMain/kotlin/dev/sk2andy/materialbrowser/shared/transfer/`.

## Что переносится
- Имя устройства, открытые вкладки (адрес, заголовок), закладки (адрес, заголовок, папка).
- Пароли и история в версию 1 **не входят**.
- Только адреса `http`/`https` с хостом: `javascript:`, `file:`, `intent:` и прочее отбрасываются
  при отправке и отвергают весь пакет при приёме.
- Лимиты: 500 вкладок, 10 000 закладок, адрес до 8192 символов, заголовок и папка до 1024,
  имя устройства до 80, весь пакет до 16 МиБ.

## Слияние на принимающем телефоне
- Закладки — только недостающие; совпадение по `bookmarkKey` (схема и хост в нижнем регистре,
  без порта по умолчанию и без `/` пустого пути; путь, запрос и фрагмент как есть).
- Вкладки — все, одной новой группой с именем отправившего устройства.

## Протокол `vola-pair:v1`
1. Отправитель открывает одноразовый HTTP-сервер на эфемерном порту в Wi-Fi и показывает QR:
   `vola-pair:v1?h=<IPv4>&p=<порт>&s=<session 16 B>&k=<key 32 B>&e=<unix-время конца>`
   (base64url без `=`). Срок — 2 минуты, допуск расхождения часов — 30 с.
2. Получатель сканирует код и делает **один** запрос `POST /v1/<session>` с телом
   `{"v":1,"nonce":<16 B>,"proof":HMAC(authKey, "vola-pair/v1/request" ‖ session ‖ nonce)}`.
3. Отправитель проверяет proof за постоянное время и отвечает
   `{"v":1,"iv":<12 B>,"ct":AES-256-GCM(encKey, iv, payload, aad)}`,
   где `aad = "vola-pair/v1/payload" ‖ session ‖ nonce`. После ответа сервер закрывается.
4. Ключи: `authKey = HMAC(key, "vola-pair/v1/auth-key")`,
   `encKey = HMAC(key, "vola-pair/v1/encryption-key")`. Ключ из кода напрямую не используется.

Криптография — через порт `LocalTransferCrypto` (на Android — `javax.crypto`, `SecureRandom`);
в тестах — детерминированная подделка.

## Модель угроз
| Угроза | Защита |
|---|---|
| Чужое устройство в той же Wi-Fi забирает пакет | без ключа из QR нельзя сделать proof; ответ зашифрован |
| Подслушивание Wi-Fi | содержимое — только AES-GCM; ключ идёт только через экран |
| Повтор старого ответа | AAD содержит nonce нового запроса — старый ответ не откроется |
| Подмена ответа | тег GCM; получатель отвергает пакет целиком |
| Перебор / «выжигание» сессии чужими запросами | неверный proof не тратит сессию; адаптер закрывает предложение после нескольких неверных запросов (`TooManyAttempts`) |
| Код ведёт на сервер в интернете, на loopback или link-local | хост — только частный IPv4 (10/8, 172.16/12, 192.168/16) без ведущих нулей |
| Вредный пакет: огромный, со скриптовыми ссылками | строгий JSON с точным набором полей, лимиты, только http/https |
| Ключ в логах | `LocalTransferPairing.toString()` ключ не печатает |
| Давний код со скриншота | срок 2 минуты; код с концом дальше срока + допуск тоже отвергается |

Чего протокол **не** защищает: человека, который видит экран отправителя в эти 2 минуты (он
может сам отсканировать код). Поэтому отправка — только по явному нажатию и закрывается после
первого успешного переноса.
