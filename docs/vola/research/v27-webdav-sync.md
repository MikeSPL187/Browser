# V27: синхронизация через свой сервер WebDAV

Шаг 2 плана H (#80, комментарий 6232799116; контракт экранов — 6233064338): исследование, протокол
и порт в `shared`, без Android. Код — `shared/src/commonMain/kotlin/dev/sk2andy/materialbrowser/shared/sync/webdav/`.

## Решения владельца (17.10, ~13:20)
- Синхронизируются **вкладки и закладки**; пароли и история — позже.
- **Сквозное шифрование фразой**: Argon2id + AES-256-GCM. Сервер видит только зашифрованные файлы;
  забытую фразу не восстановить.
- **Когда:** при открытии Vola, при уходе из неё и по кнопке «Синхронизировать сейчас». Фоновых задач нет.

## Раскладка на сервере
Всё лежит в папке `Vola/` в корне WebDAV:

| Файл | Что внутри | Кто пишет |
|---|---|---|
| `Vola/vola.json` | заголовок открытым JSON: версия, id пространства (16 B), соль Argon2id (16 B), параметры (64 МиБ, 3 прохода, 4 потока), проверочное значение | первое устройство; «Начать заново» |
| `Vola/devices/<id>.json` | запись устройства, AES-256-GCM: имя, номер версии, время, открытые вкладки, его взгляд на все закладки | только это устройство |

- Id устройства — 16 случайных байт (base64url, 22 знака). В именах файлов нет ни имени устройства,
  ни адресов.
- **Каждое устройство пишет только свой файл**, поэтому два устройства никогда не спорят за один
  файл. Общий только заголовок, и его создаёт один раз первое устройство.
- Лимиты — как у V26: 500 вкладок, до 20 000 записей закладок (живые и надгробия), запись до 16 МиБ,
  не больше 50 других устройств за одну синхронизацию. Только адреса `http`/`https`.

## Ключи
- `vaultKey = Argon2id(фраза, соль)`, 32 байта. Хранится в Keystore **ключ, а не фраза**: фраза не
  лежит нигде, экран её после ввода не держит.
- `encKey = HMAC-SHA256(vaultKey, "vola-webdav/v1/encryption-key")`.
- Проверочное значение заголовка — `AES-GCM(encKey, "vola-webdav/v1/check")` с AAD = метка + id
  пространства. Если оно не открывается — фраза не та (`PhraseMismatch`), и на сервере ничего не трогаем.
- Файл устройства — `AES-GCM(encKey, запись)` с AAD = `"vola-webdav/v1/device"` ‖ id пространства ‖
  id устройства: сервер не может выдать файл одного устройства за другое или файл из старого
  пространства за новый.
- Параметры Argon2 в заголовке проверяются **точно**: сервер, который понизит стоимость, не заставит
  телефон вывести слабый ключ — фраза просто перестанет подходить.

## Синхронизация
1. `GET vola.json`: тот же заголовок, ключ его открывает. Нет заголовка (данные удалили с другого
   устройства) — пишем его заново, раз это устройство всё ещё подключено. Другое пространство —
   `PhraseMismatch`.
2. `PROPFIND Depth: 1` на `devices/`: имена и `ETag`. Файл с прежним `ETag` заново не качается.
3. Слияние закладок (ниже), затем телефон применяет изменения у себя.
4. `PUT devices/<id>.json` с `If-Match: <ETag из шага 2>` (первый раз — `If-None-Match: *`).
   `412` — файл изменился без нас (например, тот же id восстановлен из резервной копии на втором
   телефоне): читаем заново и повторяем один раз.

Порядок важен: **сначала применить, потом запомнить**. Движок (`WebDavSyncEngine`) делит
синхронизацию на `pull` и `push`, а в `push` адаптер передаёт закладки, которые телефон реально держит
после применения. Иначе закладка, не влезшая в лимит «Избранного» (100), на следующей синхронизации
выглядела бы удалённой и удалилась бы на всех устройствах.

### Закладки: слияние с надгробиями
- Каждая закладка — запись по `bookmarkKey` (как в V26): адрес, заголовок, папка, время изменения,
  признак удаления. Удалённая закладка остаётся **надгробием** 180 дней.
- Слияние — «последняя запись побеждает» по времени изменения; при равном времени побеждает
  удаление, затем больший заголовок, папка, адрес. Результат не зависит от порядка и повторов, так
  что все устройства приходят к одному и тому же.
- Время ставит устройство, которое изменило закладку: `max(сейчас, прошлое время + 1)`, так что даже
  отстающие часы двигают изменение вперёд.
- **Первая синхронизация** устройства: про возраст его закладок ничего не известно, поэтому они
  считаются самыми старыми (время 0). Удаление, которое другое устройство уже синхронизировало, их
  побеждает; закладки, которых на сервере нет, добавляются туда.
- Устройство, которое не синхронизировалось дольше 180 дней, может вернуть удалённую закладку. Это
  осознанная граница: без неё надгробия копились бы вечно.

### Вкладки
Устройство публикует свои открытые веб-вкладки (адрес, заголовок). Другие устройства их только
показывают («Вкладки устройства»); открыть — обычным нажатием. Вкладки не сливаются.

## Сервер
- **Только HTTPS.** Сертификат проверяет система; «доверять любому» не делаем. Адрес с логином внутри,
  с `?` или `#`, с `..` в пути отвергается. `http://` — `NotHttps` (экран ловит сам, порт тоже).
- **Перенаправления не выполняем**: иначе сервер мог бы увести пароль на другой хост или на `http`.
- **Nextcloud:** для голого адреса сначала пробуем `remote.php/dav/files/<логин>/`, затем сам адрес.
  Вход — пароль приложения (Basic). Логин в пути — id пользователя Nextcloud; при входе по почте
  id может отличаться, тогда адрес вводят полностью.
- Определение WebDAV — `PROPFIND Depth: 0` с ответом `207`. `401`/`403` — `LoginRejected`.
- Разбор `207 Multi-Status` — свой, по локальным именам тегов, без DTD и сущностей (XXE невозможен),
  ответ до 4 МиБ.

## Модель угроз
| Угроза | Защита |
|---|---|
| Владелец сервера или хостинг читает данные | всё, кроме заголовка, — AES-256-GCM; ключ только на устройствах |
| Перебор фразы по файлам с сервера | Argon2id 64 МиБ × 3; длина фразы не меньше 10 знаков (экран) |
| Сервер подменяет или правит файл | тег GCM; файл не открылся — устройство пропускается |
| Сервер выдаёт файл одного устройства за другое | id устройства и пространства в AAD |
| Сервер возвращает старую копию файла устройства | номер версии в записи растёт; старая копия игнорируется |
| Сервер понижает параметры Argon2 | параметры проверяются точно |
| Перехват в сети | только HTTPS с системной проверкой сертификата, без перенаправлений |
| Злой сервер шлёт огромный или кривой ответ | лимиты на тело, строгий JSON, свой разбор XML без сущностей |
| Два устройства подключаются одновременно | заголовок пишется с `If-None-Match: *`; проигравший читает чужой и проверяет фразу |
| Тот же id на двух телефонах (резервная копия) | `If-Match`; адаптер исключает файлы синхронизации из резервной копии |
| Удаление закладки возвращается с другого устройства | надгробия 180 дней |
| «Начать заново» на одном устройстве | новый id пространства; остальные видят `PhraseMismatch` и ничего не перезаписывают |
| Пароль или ключ в логах | `toString()` аккаунта и заголовка их не печатает |

**Чего протокол не защищает.**
- Метаданные: сервер видит число устройств, размеры файлов и время синхронизаций.
- Удаление: сервер может удалить или не отдать файлы — синхронизация остановится, но подменить
  данные он не сможет.
- Откат всего пространства: сервер может откатить все файлы разом; устройство заметит только откат
  файлов, которые оно уже видело в более новой версии.
- Забытая фраза: данные на сервере не восстановить, остаётся «Начать заново». Данные на телефонах
  при этом не теряются.

## Порт для экранов (`RemoteSyncPort`)
По контракту H:
- `connect(address, login, appPassword, phrase, onResult)` → `Connected` или `Failed(reason)`.
  Причины: `Unreachable`, `LoginRejected`, `NotHttps`, `NotWebDav`, `PhraseMismatch`.
  `PhraseMismatch` включает и повреждённый заголовок: человек в обоих случаях решает одно —
  ввести фразу ещё раз или начать заново.
- `state` и `addListener`: сервер, время последней синхронизации, идёт ли синхронизация, последняя
  ошибка, другие устройства (id, имя, число вкладок, время).
- `syncNow()`; синхронизация при открытии и уходе — на стороне адаптера.
- `deviceTabs(deviceId)` — вкладки устройства.
- `disconnect(deleteServerData)`: без удаления убирает с сервера только файл этого устройства,
  чтобы другие перестали его показывать.
- `startOver(onResult)`: после `PhraseMismatch` при подключении — удаляет данные и подключается с
  введённой фразой; при подключённом сервере — удаляет данные и начинает заново с той же фразой.
- Минимальная длина фразы 10 (`V5WebDavRules.MIN_PHRASE`) — достаточно при Argon2id 64 МиБ:
  менять не нужно. В подсказке под полем лучше советовать «несколько слов».

## Адаптер Android (шаг 3, I)
- `WebDavRemoteSync` (shared) — реализация `RemoteSyncPort`: сеть и Keystore на одном фоновом
  потоке, библиотека и состояние — на главном; одна синхронизация за раз, запрос во время неё даёт
  ещё одну после.
- `VolaRemoteSync` — одна синхронизация на процесс: при открытии Vola и при уходе из неё
  (`ProcessLifecycleOwner`: переходы между своими экранами не считаются). Только GeckoView;
  в сборке WebView экраны показывают `RemoteSyncPort.Unavailable`.
- Синхронизация принадлежит профилю, который был активен при подключении; пока активен другой,
  она ждёт, чтобы закладки другого профиля не сочлись удалениями.
- Если человек изменил «Избранное», пока шла синхронизация, изменения сервера в этот раз не
  применяются: следующая синхронизация увидит правку как правку.
- HTTPS — OkHttp (уже в зависимостях): `followRedirects(false)`, тайм-ауты, лимит тела,
  системные сертификаты. Argon2 — тот же, что у `SyncCrypto`.
- Аккаунт и память — `AndroidSyncSecretProtector` с отдельным ключом Keystore, файлы в
  `noBackupFilesDir`.

Новых зависимостей нет: OkHttp, Argon2 и `kotlinx.serialization` уже были.
