# Модернизация движка без форка Gecko — идеи на будущее

Статус: **отложено, решение владельца позже** (запись от 2026-10-11). Ничего из этого не в работе, пока
владелец не выберет. Свой форк Gecko (C++/Rust) не делаем: сборка неподъёмна для CI, а правки пришлось бы
переносить на каждый выпуск Firefox раз в 4 недели (правило 6 — всегда последний stable GeckoView).

## Что можно сделать своими силами

1. **Настройки Gecko** (через `CandyGeckoPrefsBridge`):
   - безопасность: строгий режим без JIT как опция (для недоверенных сайтов или всегда); DNS по HTTPS с
     выбором провайдера; ECH (шифрование имени сайта при соединении); запрет утечки IP через WebRTC;
     отключение предзагрузки и спекулятивных соединений;
   - приватность: изоляция cookie по сайтам, защита от отпечатков с исключениями (часть уже в #176 и #180);
   - производительность: число процессов страниц, кэш, соединения, поведение при нехватке памяти.
2. **Встроенное расширение:** свой блокировщик уровня uBlock Origin (сетевые и косметические правила —
   уже следующий шаг дорожки F), очистка трекинговых параметров ссылок, обход AMP, cookie-баннеры,
   сигналы страницы для интерфейса.
3. **Делегаты GeckoView:** перехват навигации, разрешения, загрузки, медиа, пароли и автозаполнение,
   перевод на устройстве (Firefox Translations), встроенный PDF.
4. **Вкладки и память:** выгрузка фоновых вкладок (закрыть сессию, сохранить состояние), ленивый
   запуск движка, предзагрузка следующей страницы, профили компиляции для старта.
5. **Размер и старт:** отдельные APK под архитектуры (только arm64), чистка ресурсов, прогрев движка.
6. **Точечная подмена Java-слоя GeckoView** — только без другого выхода (пример — заглушки FIDO, #182).

Недоступно без форка: ядро на C++/Rust (JS-движок, отрисовка, песочница процессов).

## Предложенный порядок (если владелец одобрит)

1. Свой блокировщик (дорожка F, уже в плане).
2. Профиль «Усиленная безопасность»: DoH, ECH, режим без JIT как опция.
3. Выгрузка фоновых вкладок (память).
4. APK под архитектуры (размер).
