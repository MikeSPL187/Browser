# V22 · «Повторить» у неудачной загрузки — что можно повторить честно

Доклад сессии G, 2026-10-15. Только чтение кода; на устройстве не проверялось. Экран делает E, порт — G.

## Откуда берутся загрузки и что о них известно

| Путь | Где | Что известно после сбоя | Cookie |
|---|---|---|---|
| Gecko, ответ страницы (`onExternalResponse`) | `GeckoViewRuntimeHandle` → `GeckoDownloadTransfer.startResponse` | адрес ответа, имя, тип, Referer. **Метод запроса неизвестен:** `WebResponse` его не несёт, это мог быть POST (выгрузка CSV по кнопке формы) | Gecko держит их в своём хранилище профиля, Vola их не видит |
| Gecko, «Загрузить ссылку» (`startContextDownload`) | там же, `start` | адрес, Referer, имя; метод всегда GET | то же; изолированный профиль и частная вкладка — без cookie (V29, `GeckoDownloadFetchRules`) |
| WebView, обычная вкладка | `BrowserDownloadManager.enqueue` → системный `DownloadManager` | строка DownloadProvider: адрес, имя, тип, причина сбоя | Cookie передаётся заголовком, **и DownloadProvider хранит его в своей базе** |
| WebView, частная вкладка | `SystemWebViewPrivateDownload` | только в памяти (`DownloadRuntimeRegistry`) | не передаётся |
| `blob:` (оба движка) | `SystemWebViewBlobDownload`, Gecko | адрес blob живёт, пока открыта страница | — |

Сбойная загрузка Gecko хранится только в памяти процесса (`DownloadRuntimeRegistry`): частичный файл удаляется (`rollback`), после перезапуска приложения строки нет. Это нас устраивает: адрес и cookie на диск не попадают.

## Что повторяем

1. **Gecko, «Загрузить ссылку» — да.** Тот же GET с тем же Referer, теми же флагами (частная вкладка, без cookie для изолированного профиля) и тем же предложенным именем. Cookie подставляет сам Gecko из своего хранилища — Vola их не хранит.
2. **Gecko, ответ страницы — да, но с защитой.** Повтор идёт GET-запросом. Если исходный запрос был POST, сервер ответит иначе: ошибкой или HTML-страницей. Защита: сохраняем ответ, только если код 2xx и тип совпадает с объявленным в первый раз (`text/html` вместо `application/pdf` — отказ). Иначе — «Не удалось повторить, откройте страницу снова». Подменённый файл не сохраняем никогда.
3. **WebView, обычная вкладка — да.** Новая постановка в `DownloadManager` по адресу из строки DownloadProvider. Cookie берём в момент повтора из `CookieManager` для этого адреса — у себя не храним. Старую строку удаляем, чтобы в списке не было двух записей.
4. **WebView, частная вкладка — да, пока вкладка жива.** Повтор тем же потоковым путём, в памяти; после закрытия частных вкладок кнопки нет.
5. **`blob:` — нет.** После ухода со страницы данных нет. Кнопка «Повторить» не показывается; вместо неё «Открыть страницу» (адрес Referer), если он есть.
6. **После перезапуска приложения:** кнопки нет ни у одной загрузки. У Gecko и частных вкладок нет и самой записи. Строка DownloadProvider у обычной вкладки WebView остаётся, но из какого профиля была загрузка, после перезапуска неизвестно, а cookie чужого профиля в неё попасть не должны (уточнено при шаге 2, 15.10).

Докачку с места обрыва (HTTP Range + If-Range) не делаем: частичный файл удаляется, а проверка ETag — отдельная задача. Повтор начинается с нуля; так и пишем.

## Порт

```kotlin
// browser/ — нейтральный порт, без типов движка
sealed interface DownloadRetry {
    data object Available : DownloadRetry
    /** Почему нельзя; UI показывает «Открыть страницу», если есть [pageUrl]. */
    data class Unavailable(val reason: DownloadRetryUnavailable, val pageUrl: String?) : DownloadRetry
}
enum class DownloadRetryUnavailable { Blob, PrivateClosed, NotRemembered }

interface DownloadRetryPort {
    fun retry(entryId: Long): DownloadRetry
    /** Новая загрузка; результат приходит как обычная строка списка. */
    fun startRetry(entryId: Long): Boolean
}
```

Для Gecko в памяти держим «билет» на каждую неудачную загрузку: адрес, Referer, имя, объявленный тип, владельца (`GeckoDownloadOwner`: профиль, частная, `contextId`) и вид (ссылка или ответ страницы). Не больше 20 билетов; билеты частных вкладок стираются вместе с ними. Для WebView обычной вкладки билет восстанавливается из строки DownloadProvider. `DownloadEntry` получает поле `retry: DownloadRetry` — экран E показывает кнопку только при `Available`.

## Шаги

1. Порт и билеты Gecko (ссылка и ответ с проверкой типа), юнит-тесты правил: что повторяемо, проверка типа, предел билетов, очистка частных.
2. WebView: повтор строки DownloadProvider с cookie из `CookieManager` профиля вкладки (пока приложение работает), удаление старой строки; частные — в памяти.
3. Инструментальный тест на сервере фикстур: сбой (обрыв соединения) → повтор → файл; ответ POST-формы → повтор отказывается при другом типе.
4. E: кнопка «Повторить» в строке над панелью и в «Загрузках».

## Попутно: известная утечка cookie (не V22)

Обычные загрузки WebView передают cookie заголовком в системный `DownloadManager`, а DownloadProvider хранит заголовки в своей базе, пока строка не удалена. Это уже записано в V29 (№ 3, для частных вкладок). Для обычных вкладок это не нарушение «ничего не пишем на диск» (вкладка не частная), но стоит знать: удаление строки из «Загрузок» стирает и cookie.
