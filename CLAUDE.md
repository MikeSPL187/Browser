# Проект: Vola — Android-браузер (форк Candy Browser, MPL-2.0)

## Контекст
- **В начале каждой сессии прочитай `docs/vola/STATUS.md`** (только текущее: открытые PR, действующие решения, следующие шаги) и обнови его в конце работы, держа коротким. Решения владельца — `docs/vola/decisions.md`, приёмы среды — `docs/vola/environment-notes.md`, история — `docs/vola/history/`: читай их, только когда нужно.
- Правила по разделам — во вложенных `CLAUDE.md` (`app/src/androidTest/`, `ui/`, `browser/gecko/`); они подгружаются, когда работаешь с файлами раздела. Новую ловушку записывай туда, а не сюда. Инструменты Claude в репозитории — `docs/vola/claude-tooling.md`.
- Владелец работает ТОЛЬКО с телефона/планшета. Нет локального ПК, нет Android Studio, нет эмулятора.
- Источник истины для сборки — GitHub Actions (.github/workflows/build.yml). Каждый PR должен собираться зелёным.
- Отвечай и пиши описания PR на русском; код, комментарии и коммиты — на английском (Conventional Commits).

## Стек
- Kotlin, Jetpack Compose, Material 3 (Expressive), JDK 17, Gradle Kotlin DSL, version catalog (gradle/libs.versions.toml).
- Движки: GeckoView (основной, flavor `full`) и Android System WebView (flavor `systemwebview`, режим поддержки: собирается и проходит CI, новые функции — только для Gecko). Обе сборки без Google Play Services: это проверяет задача `verifyNoPlayServicesDependencies` (запускается в CI).
- Все типы GeckoView/WebView — только внутри адаптеров движка. UI и ViewModel зависят лишь от engine-neutral интерфейсов.
- applicationId — `io.github.mikespl187.vola`. Kotlin-пакет `dev.sk2andy.materialbrowser` и внутренние идентификаторы Candy (имена классов, intent-действий, мостов, ассетов) сохранены намеренно: они не видны пользователю, а переименование раздуло бы диффы. Бренд меняем только в том, что видит пользователь.
- Координаты репозитория (владелец, имя, URL) — только через `VolaProject`.

## Дизайн v5: уровень AAA (решение владельца 2026-10-10)
План, решения и дорожная карта — `docs/vola/plan-v5.md`. Интерфейс, навигацию, дизайн-систему и функции строим заново; старая функция возвращается, только если она лучше решения ориентиров. Код нового интерфейса — после утверждения холста v5.
Ориентиры по важности — берём лучшее, код не копируем:
1. **Safari** — главный: чистота, типографика, плавность, адресная строка внизу, жесты, вкладки и группы, режим чтения, приватность.
2. **Zen** — минимум интерфейса вокруг страницы, закреплённые сайты.
3. **Brave** — защита по умолчанию: блокировка рекламы и трекеров, HTTPS-only, защита от отпечатков.
4. **Chrome** — привычность: поиск по вкладкам, перевод, пароли, синхронизация.

- **Цвет:** нейтральная оболочка; панель над страницей — в цвете сайта (`theme-color`); акцент профиля — на кнопках, в обзоре и на новой вкладке. Тёмная тема — тёмно-серая, как в Safari (фон около `#1C1C1E`).
- **Шрифт:** Inter Variable; шкала по образцу Safari, основной текст 17 sp.
- **Движение:** пружины и тактильная отдача по спецификации фирменных моментов (`plan-v5.md`, раздел 5); при отключённых системных анимациях — только смена прозрачности.
- **Организация вкладок:** профили как в Safari (свои cookie, история, группы, закреплённые сайты, цвет) вместо пространств.
- Новый интерфейс — под флагом `ui.v5`, экран за экраном; нынешний интерфейс (v4: «Рама»/«Воздух», пространства) работает как есть, пока его экран не заменён, но новых функций в него не добавляем.
- Все значения — только через токены из `ui/theme` (цвета, типографика, формы, motion, отступы). Никаких захардкоженных цветов/размеров.
- Поддержка телефона и планшета через WindowSizeClass.
- **Бюджеты качества** (`plan-v5.md`, раздел 7): старт, тормозящие кадры, память, размер APK, стабильность. PR, который ухудшает бюджет, краснеет в CI; доступность — не ниже обхода экранов.

## Правила
1. Не ломай разделение shared-логики и адаптеров движков. Новые функции сначала описывай как порт (interface), потом реализуй для Gecko; WebView — в режиме поддержки: где функции нет, явно скрывай её в UI.
2. Никогда не коммить keystore, пароли, local.properties, API-ключи. Подпись — только через переменные окружения в CI.
3. Перед завершением задачи запусти (если SDK доступен): `./gradlew testFullDebugUnitTest lintFullDebug`. Если SDK недоступен — скажи об этом и положись на CI.
4. Маленькие PR: одна фича — один PR, с чек-листом ручной проверки на устройстве (что нажать, что должно произойти). Для UI-изменений добавляй Compose Preview, а CI прикладывает видео сценария и preview-APK.
5. Приватность по умолчанию: никакой телеметрии, аналитики, сторонних SDK без явного запроса владельца. Приватные вкладки ничего не пишут на диск.
6. Безопасность: держи GeckoView на последней stable-версии (maven.mozilla.org), HTTPS-only по умолчанию, минимальные разрешения в манифесте.
7. Лицензия: изменённые файлы Candy остаются MPL-2.0 с исходными заголовками. Не используй бренд «Candy» в UI. Код других браузеров (Zen, Safari, Brave, Chrome) не копируем — берём только идеи.
8. Если задача неоднозначна — сначала предложи план из 3–7 шагов и жди подтверждения.
9. Интерфейс на английском и русском: каждую новую строку добавляй сразу в `values/` и `values-ru/` (lint `MissingTranslation` в CI это проверяет). Форматные плейсхолдеры (`%1$s`, `%d`) сохраняй, для множественного числа в русском заполняй формы one/few/many/other.
10. Перед началом каждой задачи порекомендуй владельцу уровень Effort (High или Extra) с кратким обоснованием: High — по умолчанию, Extra — для задач с большим числом связанных файлов, архитектуры портов движка, повторно падающего CI и аудита безопасности.
11. Параллельные сессии (несколько аккаунтов): перед любой новой задачей прочитай **доску в описании #80** (`issue_read get`: таблица «сессия, задача, ветка, файлы, статус»), комментарии после её отметки «Обновлено» и список открытых PR — весь тред читать не нужно; если задача или её файлы уже заявлены другой сессией — не начинай. Заявка до первого коммита — своя строка на доске, правкой описания #80 (навык `/claim`), по завершении — «ГОТОВО · PR #N» или «СНЯТО» в той же строке; передача работы другой сессии — навык `/handoff`. Чужие файлы не трогай.
12. **Сливать PR — только по слову владельца**, даже если CI зелёный; релиз — тоже по его слову. Исключение (решение владельца 2026-10-10): ведущая сессия сливает свои PR сама при зелёном CI и без конфликтов (`decisions.md`). Слияние через GitHub-инструмент спрашивает подтверждение (`.claude/settings.json`) — это и есть «слово», обходить его нельзя.

## Полезные команды
- Debug: `./gradlew assembleFullDebug`
- Release (в CI): `./gradlew assembleFullRelease`
- Тесты: `./gradlew testFullDebugUnitTest`
