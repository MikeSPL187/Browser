# Проект: Vola — Android-браузер (форк Candy Browser, MPL-2.0)

## Контекст
- Владелец работает ТОЛЬКО с телефона/планшета. Нет локального ПК, нет Android Studio, нет эмулятора.
- Источник истины для сборки — GitHub Actions (.github/workflows/build.yml). Каждый PR должен собираться зелёным.
- Отвечай и пиши описания PR на русском; код, комментарии и коммиты — на английском (Conventional Commits).

## Стек
- Kotlin, Jetpack Compose, Material 3 (Expressive), JDK 17, Gradle Kotlin DSL, version catalog (gradle/libs.versions.toml).
- Движки: GeckoView (основной, flavor `full`) и Android System WebView (flavor `systemwebview`). Обе сборки без Google Play Services: это проверяет задача `verifyNoPlayServicesDependencies` (запускается в CI).
- Все типы GeckoView/WebView — только внутри адаптеров движка. UI и ViewModel зависят лишь от engine-neutral интерфейсов.
- applicationId — `io.github.mikespl187.vola`. Kotlin-пакет `dev.sk2andy.materialbrowser` и внутренние идентификаторы Candy (имена классов, intent-действий, мостов, ассетов) сохранены намеренно: они не видны пользователю, а переименование раздуло бы диффы. Бренд меняем только в том, что видит пользователь.
- Координаты репозитория (владелец, имя, URL) — только через `VolaProject`.

## Дизайн: визуальный ориентир — Zen Browser
Главный образец эстетики — Zen Browser (десктопный Firefox-форк, наследник стиля Arc). Мы переносим его идеи на мобильный Android, а не копируем пиксель в пиксель.
Zen в приоритете, но не единственный ориентир: лучшие решения других браузеров (Arc Search, Safari, Vivaldi, Firefox, Brave и др.) тоже берём, если они делают Vola красивее, удобнее, быстрее, функциональнее или безопаснее.
- **Минимум интерфейса вокруг страницы:** контент от края до края, панели появляются только когда нужны.
- **Мягкая эстетика:** плавные градиенты (в т.ч. акцентный градиент на Workspace), крупные скругления, лёгкая полупрозрачность и размытие фона панелей, аккуратные тени.
- **Движение:** пружинные анимации (spring), плавные переходы между вкладками и пространствами, тактильная отдача на ключевых жестах.
- **Цвет:** динамический цвет Material You как база; у каждого Workspace свой акцентный цвет, который тонирует панели.
- Тёмная и чистая OLED-тема обязательны.
- Все значения — только через токены из `ui/theme` (цвета, типографика, формы, motion, отступы). Никаких захардкоженных цветов/размеров.
- Поддержка телефона и планшета через WindowSizeClass.

### Фичи в духе Zen (целевые, реализуются отдельными PR)
1. **Workspaces** — отдельные пространства вкладок (например «Работа», «Аниме», «Личное») со своим названием, иконкой/эмодзи и акцентным цветом. Переключение свайпом по нижней панели и через меню. У каждого пространства свой набор вкладок и закреплённых сайтов.
2. **Закреплённые сайты (Essentials)** — сетка избранных иконок сверху обзора вкладок, общая или своя для Workspace.
3. **Compact Mode** — режим, где адресная строка и панели скрыты, страница на весь экран; панель появляется свайпом от нижнего края или при прокрутке вверх. Включается переключателем и запоминается.
4. **Split View** — две вкладки рядом (на планшете по горизонтали, на телефоне по вертикали) с перетаскиваемым разделителем.
5. **Моды/темы** — пользовательские темы интерфейса (набор токенов): выбор из готовых + редактор акцента, скругления и плотности.
6. **Glance** — быстрый предпросмотр ссылки во всплывающем окне по долгому тапу без открытия новой вкладки.

## Правила
1. Не ломай разделение shared-логики и адаптеров движков. Новые функции сначала описывай как порт (interface), потом реализуй для Gecko и WebView; если в WebView невозможно — явно скрывай фичу в UI.
2. Никогда не коммить keystore, пароли, local.properties, API-ключи. Подпись — только через переменные окружения в CI.
3. Перед завершением задачи запусти (если SDK доступен): `./gradlew testFullDebugUnitTest lintFullDebug`. Если SDK недоступен — скажи об этом и положись на CI.
4. Маленькие PR: одна фича — один PR, с чек-листом ручной проверки на устройстве (что нажать, что должно произойти). Для UI-изменений добавляй Compose Preview.
5. Приватность по умолчанию: никакой телеметрии, аналитики, сторонних SDK без явного запроса владельца. Приватные вкладки ничего не пишут на диск.
6. Безопасность: держи GeckoView на последней stable-версии (maven.mozilla.org), HTTPS-only по умолчанию, минимальные разрешения в манифесте.
7. Лицензия: изменённые файлы Candy остаются MPL-2.0 с исходными заголовками. Не используй бренд «Candy» в UI. Код Zen не копируем (он десктопный) — берём только идеи дизайна.
8. Если задача неоднозначна — сначала предложи план из 3–7 шагов и жди подтверждения.
9. Перед началом каждой задачи порекомендуй владельцу уровень Effort (High или Extra) с кратким обоснованием: High — по умолчанию, Extra — для задач с большим числом связанных файлов, архитектуры портов движка, повторно падающего CI и аудита безопасности.
